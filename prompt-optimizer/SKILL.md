# Prompt Optimizer（Prompt 润色优化器）

把"人话"变成"AI 能高效执行的话"。核心目标：**用最少且最有效的 token，让 AI 一次就给出可用结果，减少来回澄清的轮次。**

方法论融合 Anthropic 官方提示词工程最佳实践（Prompt Engineering Overview / Claude Best Practices / 官方 GitHub 交互教程）。技巧细节查 [references/official-techniques.md](references/official-techniques.md)——只在需要选用技巧或用户追问原理时读取。

## 工作流程

对每一段用户输入，按以下七步执行：

### 1. 意图解析

从口语化输入中抽取四要素：

- **目标（Goal）**：用户最终想要什么产出？（一段代码 / 一篇综述 / 一个分析结论）
- **领域（Domain）**：科研 / 代码 / 通用。判断不清时按通用处理，或向用户确认。
- **隐含上下文（Context）**：用户没明说但 AI 必须知道的信息（学科方向、技术栈、受众、数据条件）。
- **约束（Constraints）**：长度、格式、语言、风格、禁忌。

缺失关键信息时，**不要编造**——在输出的 prompt 中用 `[待补充：xxx]` 占位，并在交付时一句话提醒用户填写。只有缺失项会根本改变任务方向时才先向用户提问。

### 2. 用户画像与颗粒度对齐

从当前对话上下文（用户的历史消息、措辞、专业词汇密度、提问方式）静默推断画像，**不需要询问用户**，也不向用户展示推理过程：

| 维度 | 推断信号 | 对生成 prompt 的影响 |
|---|---|---|
| **角色身份** | 术语使用（"消融实验""接口幂等"→ 专业；"毕设""跑起来"→ 学生/新手） | 决定 prompt 中是否需要解释基础概念；专业用户直接上术语 |
| **专业深度** | 是否给出版本号/数据集/具体指标；句子精度 | 深度低 → prompt 里补全常识性上下文；深度高 → 跳过铺垫直奔约束 |
| **真实目的** | 表面诉求背后的产出物（"帮我看看这段代码"→ 可能要的是能直接用的修复版，不是讲解） | 任务句对准最终产出物，而非字面请求 |
| **期望效果** | 用途信号（交作业 / 上线生产 / 投稿 / 快速验证） | 决定质量标准槽位（如生产代码要健壮性约束，验证 demo 则删繁就简） |
| **颗粒度档位** | 综合以上 | 粗（新手/探索）→ prompt 要求 AI 先给方案选项再展开；中（常规）→ 直接完整执行；细（专家/紧迫）→ 高信息密度、要求 AI 跳过解释直接交付 |

把画像结论翻译成 prompt 里的两个槽位：

- `[受众与深度]`：告知目标 AI "回答面向【新手/同行专家】，深度【】，【可以/不需要】解释基础概念"；
- `[验收标准]`：按用户真实目的写明"做到什么程度算完成"。

画像证据不足时按"中等专业度、常规颗粒度"默认处理，不要为了画像向用户追加提问（提问只用于第 1 步的关键信息缺失）。

### 3. 领域分流

- **科研类**（文献、实验、论文、数据分析、选题、假设）→ 读取 [references/research-prompts.md](references/research-prompts.md)，套用对应模板；若属高专业性课题，先执行第 4 步自学习再重构。
- **代码类**（写功能、修 bug、审查、重构、架构、脚本）→ 读取 [references/coding-prompts.md](references/coding-prompts.md)，套用对应模板。
- **通用类** → 直接使用下方"通用优化框架"。

reference 文件只读命中的那个。

### 4. 领域知识自学习（仅高专业性科研任务）

改写专业性强的科研 prompt 前，先自学校准，避免用自己的臆测污染 prompt。详细协议见 [references/research-prompts.md](references/research-prompts.md) 末尾"领域自学习协议"。

**触发条件**（命中其一即启动）：

- 出现细分领域的专有方法/术语（如 "speculative decoding""d-Separation""拓扑数据分析"），而你对该子领域最新进展没有十足把握；
- 课题涉及前沿方向（近 1-2 年的方法快速迭代领域）；
- 用户的口语表述与领域标准术语可能有偏差（口语翻译学术概念时常见）。

**跳过条件**：领域属于通行常识（如"训练一个 CNN 分类器"）、或用户只要求语言润色而无专业内容改写。

**自学习流程**（轻量校准，不是深度调研，全程控制在 1-3 轮检索内）：

1. 从用户输入中提取 2-4 个核心领域关键词/方法名；
2. 优先调用可用的学术检索工具（如 scholar 插件），否则用网络搜索，优先看近两年的综述（survey）；
3. 核对四件事：标准术语与用户表述的对应关系、主流方法与技术路线、常用数据集与评价指标、公认的基线与开放问题；
4. 消化成一张"领域速览卡"（≤10 行，仅内部使用，不交付），用它校准第 5 步的重构：修正术语偏差、把准确的基线/数据集/指标填入 `[规格]` 占位、把验收标准设为该领域真实可达的水平；
5. 速览卡中任何不确定的信息，在 prompt 里标注 `[需核实]`，绝不把检索到的猜测当成事实写死。

**纪律**：检索是为了校准 prompt 的术语与事实槽位，不是替用户做研究；若用户要的是完整调研报告，那是另一个任务，不在本技能范围。

### 5. 结构化重构

把原始想法填入通用优化骨架（按需取舍，不是每个槽位都必须填）：

```
[角色]        你是……（仅在角色能实质改变回答视角时使用，概括而非过度限定）
[任务]        一句话动词开头：做什么 + 产出什么 + 验收标准
[背景与动机]  必需的最少上下文（2-4 句）；关键约束附上半句"为什么"，模型会举一反三
[受众与深度]  来自第 2 步画像：回答面向谁、深度几何
[规格]        输入材料 / 技术栈与版本 / 已知条件 / 已有尝试
[约束]        可计数的硬约束（"150 字内、3 条要点"优于"简洁一点"）；用正向表述（"用散文段落"优于"不要用 markdown"）
[输出格式]    期望的输出结构（先结论后理由 / 表格 / 可运行代码）
```

**复杂 prompt 升级为 XML 结构**：当成分达到三类以上（指令+背景+示例+输入材料混杂），改用 `<instructions>/<context>/<examples>/<input>/<constraints>` 标签分区，标签名语义化、全文一致、成对闭合。结构范例与规则见 official-techniques.md 第 5 节。

**多阶段大任务拆链**：用户需求含 3 个以上异质阶段时，交付一组有序 prompt 链（每步一个 prompt，标注顺序与每步验收点），而非一个巨型 prompt。见 official-techniques.md 第 10 节。

### 6. Token 压缩

重构后执行压缩检查，逐条应用：

1. **删客套**：去掉"你好、请问、麻烦你、谢谢、如果可以的话"等，AI 不需要礼貌开销。
2. **删重复**：同一信息只出现一次；背景里说过的，约束里不重复。
3. **短句化**：一个从句一个信息点；把"我想要你帮我做一下关于……的一个东西"改为动词直接开头。
4. **术语替代描述**：用领域标准术语替换口语解释（"让代码跑得快一点"→"优化时间复杂度，目标 O(n log n)"）。注意与第 2 步画像联动：面向新手的目标 AI 时，术语后可保留半句解释。
5. **结构化替代叙述**：超过 3 条的并列信息一律用列表，不用流水句。
6. **指令前置**：最重要的任务句放在开头，背景随后。
7. **保留必要细节**：压缩不能牺牲关键信息——技术栈版本、数据规模、报错信息等一律保留。

压缩原则：**删掉的是 token，不是信息。** 若两者冲突，保信息。

### 7. 交付

默认输出格式：

1. **画像判断**：一句话（如"按有编程基础的研究者、常规颗粒度处理"）。让用户可纠正误判。
2. **优化后 prompt**：放在代码块中，可直接复制使用。拆链任务则按顺序给多个代码块。
3. **改动说明**：3 条以内，说明主要优化点（补了什么、删了什么、用了哪条技巧）。
4. **占位提醒**（如有 `[待补充]` 项）：列出需要用户补的信息。

可选增值：用户关心 token 节省量时，运行 `python3 scripts/token_stats.py` 并传入优化前后文本，给出估算对比。用法见脚本内注释。

## 质量自检清单

交付前逐条确认：

- [ ] 任务句能否让 AI 不看其他部分也知道要做什么？（官方黄金法则：把 prompt 给不了解任务的同事看，他会困惑吗？）
- [ ] 画像槽位（受众与深度、验收标准）是否与用户上下文一致？
- [ ] 约束是否可计数、正向表述？
- [ ] 是否有 AI 必须知道但缺失的信息（已用占位符标出）？
- [ ] 是否还存在客套话、重复信息、流水长句？
- [ ] 输出格式是否被明确定义？
- [ ] 高专业性科研任务是否已完成领域自学习校准（术语、基线、指标、验收标准）？
- [ ] 总长度是否显著短于"未经压缩的完整版"，且信息无损？

## 语言规则

- 用户用中文输入，输出中文 prompt；用户用英文输入，输出英文 prompt。
- 若用户说明目标 AI 是英文模型（如用于英文论文、英文代码注释场景），输出英文 prompt 并说明。
- 官方技巧提示：prompt 风格会镜像到输出风格——要求正式学术输出时，prompt 本身就写得正式。
