提炼自 Anthropic 官方文档（Prompt Engineering Overview、Claude Prompting Best Practices、Claude 4 Best Practices）及官方 GitHub 交互教程（anthropics/prompt-eng-interactive-tutorial，9 章体系）。生成 prompt 时按需引用这些技巧，不要全部堆砌——简单任务用简单 prompt。

## 1. 清晰直接（黄金法则）

官方检验标准：把 prompt 拿给一个几乎不了解任务的同事看，如果他会困惑，模型也会。把 AI 当作"聪明但毫无背景信息的新员工"。

应用：任务句必须包含**动词 + 产出物 + 验收标准**。对比：

- 弱："做个分析面板"
- 强："做一个销售分析面板，包含趋势图、地区对比、Top10 商品三个模块，数据用我上传的 csv"

## 2. 说明"为什么"（动机式上下文）

给出指令背后的原因，模型会举一反三，比孤立规则效果好。

- 弱："不要用省略号"
- 强："输出会被语音合成朗读，省略号无法发音，请用完整的标点断句"

应用：为关键约束附上半句理由，尤其是格式类和禁区类约束。

## 3. 可计数的硬约束

模糊副词是 token 浪费且效果差。把一切"简洁/详细/短一点"替换为数字：

- 弱："回答简洁一点"
- 强："回答不超过 150 字，最多 3 条要点"

## 4. 正向表述

否定式指令要求模型先想象被禁止的行为，效果差且可能反向强化。改写对照：

- 弱："不要用 markdown"
- 强："用连贯的散文段落回答"

应用：检查生成 prompt 中的每一个"不要/禁止/避免"，能转为正向表述的一律转写；只有真正的安全禁区保留否定式。

## 5. XML 标签结构化

当 prompt 同时包含指令、背景、示例、输入材料**四类成分中的三类以上**时，用 XML 标签分区（官方推荐的 Claude 最优结构）：

```
<instructions>任务与步骤</instructions>
<context>背景信息</context>
<examples><example>输入→输出样例</example></examples>
<input>待处理的材料</input>
<constraints>硬约束</constraints>
```

规则：

- 标签名语义化且全文一致，正文引用时用同名标签（"根据 `<context>` 中的信息……"）
- 层级内容用嵌套（`<documents><document index="1">…`）
- 每个开标签必须闭合
- 短 prompt（一两句话）不要用标签——标签的收益在多成分复杂 prompt

## 6. 少样本示例（multishot）

对格式微妙、难以用语言描述的任务，给 2-5 个输入→输出示例，放在 `<examples>` 中。示例必须与期望行为严格一致——模型会放大示例中的任何模式，包括错误模式。

## 7. 角色设定

角色有效但要**概括而非过度限定**：

- 弱："你是一位有 23 年经验、得过图灵奖、只研究 Transformer 的科学家"
- 强："你是机器学习方向的资深研究员，熟悉系统优化"

仅在角色能实质改变回答视角时使用；纯事实问答不设角色。

## 8. 思考与自检

- 复杂推理任务：让模型先在 `<thinking>` 中逐步推理，再在 `<answer>` 中给最终答案，推理与输出分离。
- 代码/数学/事实类任务结尾追加自检指令："完成前对照【验收标准】逐项核验答案。"——追加式，零结构成本，官方验证可靠。

## 9. 引用锚定（防幻觉）

处理长文档/文献时，要求模型**先摘引原文再作答**：

"先从文档中摘出与【问题】相关的原文引句放入 `<quotes>`，再基于引句作答。"

这是官方文档中最有效的防幻觉手段，同时产出可审计的证据链。科研文献场景必加。

## 10. 提示词链（prompt chaining）

任务含 3 个以上异质阶段（如：调研→列提纲→写作→审校）时，不要塞进一个巨型 prompt，拆成有序的小 prompt 链，每步输出作为下一步输入，每步之间可验证可修正。

应用：当用户需求明显是多阶段大任务时，交付物可以是"一组有序 prompt"而非单个 prompt，并标注执行顺序与每步验收点。

## 11. 风格镜像

输出风格会镜像 prompt 自身的风格：啰嗦的 prompt 产出啰嗦的回答，markdown 密集的 prompt 产出 markdown 密集的回答。

应用：想要正式学术输出就把 prompt 写得正式；想要电报式简报就把 prompt 写得简短。

| 任务描述含糊 | 1 清晰直接 + 3 硬约束 |
| 格式/禁区类要求 | 4 正向表述 + 2 说明为什么 |
| 成分多、材料杂 | 5 XML 标签 |
| 格式难以言喻 | 6 少样本示例 |
| 需要专业视角 | 7 角色设定 |
| 多步推理/易错计算 | 8 思考与自检 |
| 基于长文档/文献 | 9 引用锚定 |
| 多阶段大任务 | 10 提示词链 |
| 指定输出语气 | 11 风格镜像 |
